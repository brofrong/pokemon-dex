# Все поколения, способности, анимации, баги: дизайн

Статус: решения приняты агентом по запросу пользователя («делай»), 2026-11-10. Дополняет `docs/draft.md`.

## Цель

1. Сайт без багов: QA-проход в браузере, исправления, e2e-тесты как страховка от регрессий.
2. Все 9 поколений, а не только Black/White. По умолчанию по-прежнему B/W.
3. Способности с описаниями.
4. Анимации живее, но быстрые, и с уважением к `prefers-reduced-motion`.

Правила данных по поколению: типы, статы, способности, таблица типов и эволюции такие, какими они были в этом поколении (уже работает для B/W). Дополнительно:
- **Способностей нет в I–II.** Скрытые способности появляются с V. Способности, появившиеся позже поколения, отбрасываются.
- **Пол, яйцевые группы, шаги до вылупления и shiny** появляются со II поколения. В I поколении эти блоки и переключатели скрыты.
- **Формы:** только те, что появились к этому поколению.
  - мега-эволюции есть только в `xy` и `sm`;
  - гигантамакс есть только в `swsh`;
  - региональные формы появляются со своего поколения.
- **Тексты покедекса EN** берутся из версий этого поколения. Если текста нет (в SwSh не все покемоны), берётся последний более ранний, с подписью версии.

## Спрайты VI–IX

Пиксельных спрайтов для этих поколений нет. Берём 3D-рендеры Pokémon HOME, один набор на все четыре поколения. Это не пиксель-арт, поэтому их можно жать агрессивно: уменьшить до 192 px (2× от 96 CSS px) и сохранить в WebP с потерями (q≈70). Есть обычный вариант, shiny и самка, вида сзади нет. Анимации у них тоже нет, атлас первых кадров есть, как и у остальных поколений. HOME именует файлы по `pokemon_id` (формы 10001+), поэтому в данных формы появляется `pokemonId`.

## Русский язык для новых поколений

- **Имена, категории и формы:** официальная локализация Pokémon GO, она покрывает около 1008 из 1025 имён. Недостающие (новейшие DLC Gen IX) переводим транслитерацией сами, это наше решение.
- **Тексты покедекса RU:** для B/W остаются наши переводы. Для остальных поколений используем официальное описание из Pokémon GO (один текст на вид, с подписью «Pokémon GO»). Чего нет в GO, переводим сами с английского текста поколения.
- **Способности:** названия и короткие описания переводим сами. EN-описания берём из `ability_prose` (short effect) и `ability_flavor_text` PokeAPI.

## Вес и лимиты

- CSS выносится из HTML в общий хэшированный файл: его кэширует Service Worker, а вес страницы покемона падает с ~49 до ~30 КБ.
  Всего около 10 800 страниц. Вместе со спрайтами (~160 МБ) это укладывается в лимит GitHub Pages в 1 ГБ.
- Главная поколения при 1025 карточках должна укладываться в ≤ 70 КБ gzip. Для этого данные для поиска и сортировки (`data-q`, `data-stats`, `data-evo`) выносятся в `/{lang}/{gen}/list.json`. Файл грузится сразу после первого экрана и кэшируется. Пока он не пришёл, поиск по имени и номеру работает по тому, что уже есть в DOM.

## Способности

На странице покемона каждая способность раскрывается по нажатию (`<details>`) и показывает короткое описание, у скрытой есть пометка. Описание берётся для языка сайта.

## Анимации

- **Главная:** карточки первого экрана появляются лёгким каскадом (опасити + сдвиг, задержка ≤ 300 мс, только при первой загрузке). При наведении карточка приподнимается, спрайт немного подпрыгивает. При фильтре и сортировке карточки плавно переезжают через same-document View Transitions.
- **Страница покемона:** полоски статов растут при появлении. Смена формы, shiny и пола проходит плавной подменой через View Transition. Стрелки эволюций мягко появляются.
- **Окно поиска ⌘K:** плавное появление.
- При `prefers-reduced-motion: reduce` всё отключено.

## Тесты

E2E-смоук на Playwright запускается против `astro preview` в CI. Проверяем главную, поиск, фильтры, страницу покемона, переключатели, ⌘K, смену языка и поколения, 404 и отсутствие ошибок в консоли.
