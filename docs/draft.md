# Pokédex: драфт

Статус: черновик для обсуждения, версия 2, 2026-11-10.

## 1. Идея и главный принцип

Статический Pokédex на GitHub Pages. Главное отличие от nationaldex.app: **моментальный отклик**.
Любое нажатие сразу что-то меняет на экране, потому что ответа сервера мы не ждём.

Как этого добиться: бэкенда нет. Все страницы и данные заранее собраны на этапе сборки. Браузер подтягивает
их в фоне ещё до клика: страницы, данные и картинки всего, что видно на экране. Дальше всё берётся из кэша.

Цели:

- первый экран по прямой ссылке рисуется сразу из HTML, без ожидания JS;
- к моменту клика страница покемона уже скачана (а в Chrome уже отрисована в фоне), поэтому переход
  моментальный;
- спрайт из карточки в списке «перелетает» на страницу покемона (CSS View Transitions);
- маленький вес: JS на странице ≤ 15 КБ gzip, HTML главной ≤ 50 КБ gzip;
- данные соответствуют выбранной генерации: типы, статы, способности и эволюции такие, какими они были
  в этой игре;
- несколько языков: `/en/` и `/ru/` в первой версии.

Не цели (пока):

- красивые карточки в стиле nationaldex (ты сказал «на потом»);
- мувы (отложили);
- аккаунты, избранное в облаке, тимбилдер.

## 2. Стек

### Инструменты: Bun 1.4

В Bun 1.4 (у нас установлен `1.4.4-canary`) всё встроено, сторонние линтеры не нужны:

- `bun lint` (с `--fix`, `--type-aware`, настройки в `bunfig.toml` в секции `[lint]`);
- `bun fmt` для форматирования. `bun format` без скрипта не работает, поэтому добавлю в `package.json`
  алиас `"format": "bun fmt"`, чтобы работали обе команды;
- `bun check` для проверки типов (те же ошибки, что у `tsc`, только на всех ядрах).

В CI гоняем `bun lint && bun fmt --check && bun check` (точный флаг проверки без записи уточню при старте).

### Фреймворк: сравнение

Что нам важно: готовый HTML для каждой страницы, предзагрузка видимых ссылок, View Transitions между
страницами, роутинг языков `/en/` и `/ru/`, минимальный JS.

| | Astro | SvelteKit (static) | Solid или Preact на голом Bun |
|---|---|---|---|
| Готовый HTML для каждой страницы | из коробки | из коробки (`adapter-static`) | пишем свой пре-рендер |
| Предзагрузка видимых ссылок | из коробки, `prefetch: viewport`, в Chrome через Speculation Rules | из коробки, `preload-data="viewport"` | пишем сами (≈ 100 строк) |
| Переходы между страницами | нативные CSS View Transitions между страницами | `onNavigate` + View Transitions | своими руками |
| Языки `/en/`, `/ru/` | встроенный i18n-роутинг | через параметр `[lang]` | сами |
| JS на странице | ≈ 0 КБ по умолчанию, интерактив кусочками | ≈ 15–25 КБ (роутер + рантайм) | 5–8 КБ + наш код |
| Сборщик | Vite (запускаем через Bun) | Vite (запускаем через Bun) | чистый `bun build` |
| Моментальный показ ещё до загрузки данных | нет, страница приходит целиком (компенсируем предзагрузкой) | да, клиентский роутер | да |

Почему в первой версии я предложил Preact: он единственный работает с JSX в Bun вообще без плагинов.
Но тогда роутер, пре-рендер, i18n и предзагрузку пришлось бы писать самим.

**Моя рекомендация: Astro.**

- Почти всё, что ты перечислил, у него встроено: готовый HTML, предзагрузка видимых ссылок, i18n
  и View Transitions между страницами (та самая CSS-фича).
- Страница покемона по сути статичная, интерактивного там почти нет. Astro отдаёт её как чистый HTML
  без фреймворка в браузере.
- Фильтры и поиск на главной делаем маленьким скриптом на TS (или островком на Solid, если станет сложно).
- Минус: под капотом сборщик Vite, а не `bun build`. Но запускается всё через Bun: `bun dev`, `bun run build`,
  `bun lint`, `bun check`.
- Второй минус: если ссылку не успели предзагрузить (быстро проскроллил и сразу нажал), браузер ждёт
  HTML с сервера (GitHub Pages обычно отвечает за 30–100 мс). Компенсируем Service Worker'ом (раздел 7).

**Если важнее мгновенный отклик даже без предзагрузки**, то SvelteKit: там клиентский роутер может нарисовать
страницу из уже известных данных до ответа сервера. Цена: больше JS и больше своего кода для переходов.

## 3. Данные

### Основной источник

CSV из репозитория [PokeAPI/pokeapi](https://github.com/PokeAPI/pokeapi/tree/master/data/v2/csv).
Это те же данные, что в API PokeAPI, но без лимитов и сетевых запросов. Скрипт `build-data.ts` скачивает CSV
и собирает компактные JSON, из которых потом генерируются страницы.

Что там есть:

- покемоны, формы, виды, типы, статы, способности, эволюции (`pokemon_evolution`, `evolution_chains`);
- **данные по прошлым генерациям**: `pokemon_types_past`, `pokemon_stats_past`, `pokemon_abilities_past`,
  `type_efficacy_past`. Например, в Black/White Клефэри Normal, Fairy-типа ещё нет;
- флаги особых покемонов в `pokemon_species`: легендарные, мифические, малыши;
- описания из покедекса по версиям игр (`pokemon_species_flavor_text`).

### Русский язык

В PokeAPI русского нет. Что есть официально по-русски: **имена покемонов**. Они используются в Pokémon GO,
UNITE, аниме и ККИ, а список ведёт Bulbapedia:
[List of Russian Pokémon names](https://bulbapedia.bulbagarden.net/wiki/List_of_Russian_Pok%C3%A9mon_names).

Для `/ru/` получается так:

| Что | Откуда |
|---|---|
| Интерфейс | переводим сами (это пара сотен строк) |
| Имена покемонов | официальные русские, со страницы Bulbapedia, один раз выгружаем в JSON |
| Названия типов | официальные из русской ККИ (их 18, переводим вручную) |
| Способности, описания из покедекса | официальных нет, см. вопросы |

## 5. Экраны

### Шапка (на всех страницах)

Слева: логотип и **переключатель генерации** (выпадашка с названиями игр и цветом версии).
Справа: переключатель языка EN / RU и темы. Поиска в шапке нет, он на главной.

### Главная: все покемоны

**Решено:** все 649 покемонов из B/W по национальному номеру, особые с пометкой.

Сетка карточек. На карточке:

- **анимированный спрайт**, анимация видна сразу (раздел 6);
- номер `#004`;
- имя;
- иконки и бейджи типов;
- **метка особого**: легендарный, мифический, малыш, новый в Unova (#494–649).

Над сеткой **крупное поле поиска** по имени и номеру (на любом языке сайта). Горячая клавиша **⌘K / Ctrl+K**
(и `/` как запасная). На главной она ставит курсор в поле, на остальных страницах открывает компактное окно
поиска поверх страницы, и выбор сразу ведёт на покемона.

Быстрые фильтры (чипы, нажатие применяется сразу):

- **по типу**: 17 иконок (в Gen V нет Fairy), можно выбрать один или два;
- **особые**: легендарные, мифические, малыши, только Unova;
- **сортировка**: номер, имя, сумма статов, отдельный стат;
- **✦ Shiny**: переключает все спрайты в сетке на шайни (отдельный атлас первых кадров).

Состояние фильтров хранится в URL (`?type=fire&sort=atk`), поэтому кнопка «назад» его не сбрасывает.

### Страница покемона

1. **Шапка**: большой анимированный спрайт (перелетает из карточки), имя, номер, типы, метка особого.
2. **Типы и слабости**: множители ×4, ×2, ×½, ×¼, ×0 по таблице этой генерации, с иконками типов.
3. **Базовые статы**: полоски, сумма, цвет по значению.
4. **Способности**: обычные и скрытая (скрытые появились как раз в Gen V).
5. **Дерево эволюции**: главная фишка, подробнее ниже.
6. **Описание из покедекса** для Black и White.
7. **Рост, вес, яйцевые группы, пол, шаги до вылупления.**

Навигация: стрелки ← → к соседним номерам (и клавиши на клавиатуре), свайп на телефоне.

### Переключатель состояний

Под типами в шапке страницы. Показываем только то, что у этого покемона реально есть:

- **Обычный / ✦ Shiny**: у всех;
- **Спереди / Сзади**: у всех;
- **♂ / ♀**: только у 106 покемонов с отличиями по полу в B/W (папка `animated/female`);
- **Формы** (Ротом, Деоксис, Кастформ, Анноун, Дарманитан и т. д.): плитки со спрайтами. Форма меняет
  не только картинку, но и типы, статы, способности и слабости на странице.

Всё переключается мгновенно, без запросов: после открытия страницы все варианты спрайта (≈ 5–15 КБ каждый)
подгружаются в фоне. Горячие клавиши: `S` Shiny, `B` сзади, `G` пол. Выбор Shiny запоминается
и сохраняется при переходах между покемонами. Форма попадает в URL (`/pokemon/rotom/?form=heat`).

### Дерево эволюции

- Строится из `evolution_chains`, **обрезанное по генерации**: в B/W у Иви нет Сильвеона, у Голбата есть
  Кробат, и так далее.
- Ветвление: Иви (7 веток в Gen V), Тирог, Поливаг, Ральтс, Виркпл.
- На стрелках условия: «Ур. 16», «Огненный камень», «Обмен», «Дружба, день», «Обмен с King's Rock».
- Текущий покемон подсвечен, остальные кликабельны. Их страницы предзагружены, переход мгновенный.
- Раскладка: цепочка горизонтально, ветвление веером. На телефоне вертикально.

## 6. Картинки

### Спрайты

PokeAPI/sprites отдаёт для B/W анимированные GIF 96×96. Спрайты пиксельные, поэтому **сжатие с потерями их
испортит**. «Агрессивно» для пиксель-арта значит так:

1. **Обрезка не нужна**: анимированные GIF B/W в PokeAPI уже обрезаны (Чармандер 41×42).
2. **Сократить палитру** и сохранить **без потерь** в WebP или AVIF (выберем замером).
3. **Анимация** в **анимированный WebP без потерь** (sharp). Замер: всего на 0–8 % легче исходных GIF, они уже оптимальны. Спрайты сзади храним статичным первым кадром: репозиторий ≈ 80 МБ вместо ≈ 170 МБ.
4. **Увеличивать в браузере**, а не в файле: `image-rendering: pixelated`. Храним 1×, показываем 2–3×.

Скрипт `scripts/sprites/build.ts` (Bun + `sharp`, только на этапе сборки). Результат коммитим в репозиторий (`public/sprites/bw/`),
только нужные файлы, а не весь PokeAPI/sprites.

### Сначала первый кадр, потом анимация

**Решено:** анимация видна сразу, но первым мгновенно показывается статичный кадр.

1. **Атлас первых кадров**: первые кадры всех 649 спрайтов в одной картинке. Один запрос, оценочно
   100–200 КБ, грузится с высоким приоритетом. Вся сетка сразу показывает покемонов.
2. **Анимированный WebP** грузится для карточек на экране и чуть ниже. Когда файл загрузился, он плавно
   подменяет первый кадр. За экраном анимации не грузятся и не крутятся (экономим батарею).
3. Пока не пришёл даже атлас (в первые миллисекунды): **силуэт в цвете типа**, задан чистым CSS.

Про **blurhash**: для крошечных пиксельных спрайтов он не нужен. Размытое пятно 96×96 весит почти как сам
первый кадр из атласа и выглядит хуже. Пригодится позже для 3D-рендеров Gen VI+, там картинки большие.

Если в будущем появятся настоящие видео: `<video poster="первый-кадр.webp" preload="none">`,
постер показывается сразу, видео подгружается после.

### Иконки типов

SVG-иконки 18 типов в одном инлайн-спрайте `<svg><symbol>`, это ≈ 3–5 КБ на все. Цвета типов
из набора. Источник: [partywhale/pokemon-type-icons](https://github.com/partywhale/pokemon-type-icons)
(MIT, указываем в футере). Набор duiker101 не подходит: у него нет лицензии.

## 7. Трюки для скорости

### Загружать всё до клика

1. **Предзагрузка видимых ссылок** (твоё требование): всё, что на экране, сразу начинает грузиться в фоне.
   - **Chrome/Edge**: Speculation Rules API. Браузер не только скачивает, а **целиком отрисовывает** страницу
     в фоне вместе с картинками. Клик показывает уже готовую страницу, 0 мс.
   - **Safari/Firefox**: `<link rel="prefetch">` для HTML и картинок видимых карточек.
   - Ограничиваем: 4–6 параллельных запросов, только в простое (`requestIdleCallback`), уважаем
     `Save-Data` и медленную сеть.
2. **Картинки заранее**: вместе со страницей предзагружаем её главный спрайт и спрайты эволюционной
   цепочки. На странице покемона так же подтягиваем соседей ← → и всю цепочку.
3. **Наведение и `pointerdown`** повышают приоритет: эта ссылка грузится первой, без очереди.

### Переход «перелёт» (View Transitions)

4. Та самая CSS-фича: **cross-document View Transitions**. Включается одной строкой
   `@view-transition { navigation: auto; }`. Спрайту в карточке и спрайту на странице покемона даём одно имя
   `view-transition-name: pokemon-25`, и браузер сам анимирует перелёт картинки, имени и плашки типа.
   - Работает в Chrome/Edge и Safari (18.2+). В Firefox, по моим данным, пока обычный мгновенный переход
     без анимации, ничего не ломается.
   - Уважаем `prefers-reduced-motion`: без анимации, если она отключена в системе.

### Первый заход

5. **Готовый HTML для каждой страницы**: прямая ссылка рисуется сразу. Заодно работает SEO и превью ссылок
   в мессенджерах.
6. **Критический CSS инлайнится в HTML**: до первого экрана нужен один запрос.
7. **Без веб-шрифтов** (системный шрифт) или один шрифт-подмножество на ≈ 15 КБ с `font-display: swap`.
   Для `/ru/` подмножество с кириллицей.
8. **`content-visibility: auto`** на карточках: браузер не рисует то, что за экраном, и 649 карточек
   не тормозят.

### Повторный заход: кэш

9. **Service Worker**. На GitHub Pages **нельзя настроить заголовки кэша**: файлы кэшируются всего на 10 минут.
   SW это исправляет:
   - оболочка, атлас и иконки кэшируются навсегда (по хэшу в имени файла);
   - страницы покемонов по стратегии stale-while-revalidate: сразу из кэша, в фоне проверяем обновление;
   - **фоновое докачивание всей генерации** (опционально, только на Wi-Fi и без `Save-Data`): после первого
     захода в простое скачиваем все 649 страниц текущего языка (оценочно 2–3 МБ). После этого любой клик
     мгновенный, даже без предзагрузки, и сайт работает офлайн.
10. **Хэши в именах файлов** (`app.3f9a.js`): обновления подхватываются сразу, а старое не протухает.

## 8. Структура проекта (набросок, под Astro)

```
scripts/
  build-data.ts        # CSV PokeAPI + русские имена → JSON по генерациям
  build-sprites.ts     # GIF → обрезка → WebP + атлас первых кадров
src/
  i18n/en.json, ru.json
  pages/[lang]/[gen]/index.astro             # список
  pages/[lang]/[gen]/pokemon/[slug].astro    # страница покемона
  components/TypeBadge.astro, EvolutionTree.astro, StatBars.astro, GenSwitcher.astro
  scripts/filters.ts, prefetch.ts, sw.ts
public/
  sprites/bw/...       # пережатые спрайты (в git)
.github/workflows/deploy.yml
```

Объём сборки: 649 покемонов × 2 языка ≈ 1300 страниц на генерацию. Для статической сборки это немного.

## 9. Риски

- **Объём репозитория.** Спрайты всех генераций могут занять сотни мегабайт. Для B/W, по оценке, 10–20 МБ.
- **Права на контент.** Спрайты и названия принадлежат Nintendo/Game Freak. Фанатские некоммерческие сайты
  обычно не трогают, но гарантий нет. Пишем дисклеймер в футере.
- **Русские имена** берём с Bulbapedia, это не официальный API. Выгружаем один раз и храним у себя.

## 10. Решения

- Языки: несколько версий сайта, `/en/` и `/ru/` в первой версии, потом можно добавить `/ja/` и другие.
- Генерации: только B/W в первой версии, архитектура под все.
- Список: все 649 покемонов, особые с пометкой.
- Анимация в списке видна сразу, первым мгновенно показывается статичный кадр из атласа.
- Мувы отложены.
- Инструменты: `bun lint`, `bun fmt` (+ алиас `bun format`), `bun check`. Без Biome.
- Фреймворк: **Astro**.
- `/ru/`: способности и описания из покедекса **переводим сами** (переводы хранятся в JSON в репозитории,
  правятся руками).
- **Фоновое докачивание всей генерации** для офлайна делаем (только Wi-Fi, без `Save-Data`).
- **Тёмная тема**: по системной настройке плюс ручной переключатель (авто / светлая / тёмная),
  выбор запоминается.
- Адрес: стандартный GitHub Pages, `<username>.github.io/pokemon-dex/`, базовый путь `/pokemon-dex/`
